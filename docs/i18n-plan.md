# 界面多语言方案框架

状态：已实现简体中文与英语界面（配置化词条、前端运行时、后端语义字段、校验脚本）。第三方 Schema Viewer 约束文案例外见 `docs/i18n-third-party.md`。

## 目标与边界

使用一套 HTML、JavaScript、CSS 和后端逻辑，通过语言配置支持简体中文与英语；后续增加语言不复制页面、业务脚本或后端模块。保留无前端构建步骤、资源本地加载的运行方式。

本次范围是完整的浏览器界面，包括工具摘要、统计、设置、错误、无障碍标签及 demo 导航。用户消息、助手原文、工具输入输出、命令、diff、路径、模型名、Schema 内容及原始 JSON 保持原文。程序生成的“未命名会话”等兜底标签属于界面文案。

README、命令行工具及安装器的多语言文档不纳入界面完成条件，可另立任务；不要通过复制 README 或应用页面来实现本方案。

## 配置与目录

拟新增以下资源；本阶段不创建这些实现文件：

```text
designs/browser/i18n.js          # 加载、查词、插值、复数及格式化
designs/browser/locales/
  manifest.json                 # 支持的语言、别名、回退语言、启用状态
  messages.schema.json          # 消息结构及词条元数据的验证约束
  messages.meta.json            # 每个 key 的用途、参数、界面位置、长度建议
  zh-CN.json                    # 基准文案，由后续实施者从源码提取
  en.json                       # 英语词条，由翻译人员填写
scripts/check_locales.py         # 结构、占位符、完整度及文件清单检查
```

不同语言的文件只承载配置值，共享同一份 key 和结构约束；不是复制应用实现。语言名称使用自称，语言别名、格式化 locale、文字方向均由 manifest 配置。

暂定 key 按功能分组：`common`、`navigation`、`session`、`tools`、`context`、`usage`、`pricing`、`errors`、`demo`、`accessibility`。key 表达语义，不以中文原文作为 key。

词条结构示意，空字符串仅表示尚未填写，不是可发布译文：

```json
{
  "common.close": "",
  "usage.scanProgress": "",
  "tools.operationCount": {"one": "", "other": ""},
  "errors.priceTls": ""
}
```

元数据另行声明，例如 `usage.scanProgress` 的参数为 `completed`、`total`，用途为扫描进度；翻译人员不需要阅读业务源码才能理解占位符。

## 运行接口

约定一个共享运行入口，具体函数名可在实施时统一：

```text
I18n.ready                       等待配置完成并确定当前语言
t(key, params)                   返回纯文本，支持命名参数
tp(key, count, params)           使用 Intl.PluralRules 选择复数形式
formatNumber(value, options)     按当前语言格式化数字
formatDate(value, options)       按当前语言格式化日期和时间
formatDuration(milliseconds)     组合可翻译的耗时单位
applyTranslations(root)          更新声明式静态文案与安全属性
```

- 只支持明确的消息结构、命名占位符和复数分支，不引入可执行表达式；首版不自制完整 ICU 解析器。
- 用完整消息表达句子，不拼接“已检查”＋数字＋“个会话”；参数顺序由译文决定。
- 译文不含 HTML、JavaScript、URL 或事件处理器。普通节点通过 `textContent` 写入；已有 HTML 模板中的结果继续经过现有 `esc()` 转义，避免注入和重复转义。
- 静态属性只允许显式列出的 `title`、`placeholder`、`aria-label` 等；不允许配置任意属性名。
- 英文复数至少支持 `one`、`other`；中文使用 `other`。新增语言按其复数类别校验。

## 初始化、选择与回退

1. 优先读取浏览器保存的显式选择，其次匹配浏览器语言列表，最后使用 manifest 的默认语言。首版默认保留简体中文；英语地区变体统一匹配 `en`。
2. 提供“跟随浏览器”和已启用语言的选择；设置保存在浏览器本地，不写入 Codex 配置，也不与价格设置混用。
3. 语言资源准备好后才启动界面初始化及数据请求。当前两个业务脚本存在顶层初始化与共享变量，实施时显式拆分启动入口并保持依赖顺序，不能仅插入异步下载脚本后继续原样启动。
4. 更新 `<html lang>` 与方向属性。加载失败使用打包的最小基准提示与重试入口，避免无限空白；离线仍从本地资源加载。
5. 首版切换语言采用保存选择后刷新当前 URL，保留会话 hash、demo 路由和已有持久化偏好。临时搜索、滚动位置及打开的弹框可能重置，界面需告知；即时无损切换作为后续增强。
6. 单条缺失或为空时，回退到基准语言并记录缺失 key；基准也缺失时显示可定位的占位提示。运行时回退用于容错，不作为英语完成的验收依据。
7. 翻译未完成的语言保留 `enabled: false`，不进入可选列表。启用英语前必须通过完整度检查。

服务端只提供明确列出的本地语言资源，不将请求中的任意 locale 拼成文件路径。同步更新 CSP 约束、静态路由和公开源码导出清单。

## 后端与前端的语言边界

后端继续负责解析、关联、统计和生成语义结果；前端负责将结果表达成当前语言。缓存、接口参数和业务判断不依赖当前语言。

后端产品文案逐步改为稳定代码与参数，例如：

```json
{
  "error_code": "pricing.tls_verification_failed",
  "message": {"key": "errors.priceTls", "params": {}},
  "details": {"exit_code": 60}
}
```

- 普通 JSON 与 NDJSON `error` 使用相同描述结构。为迁移保留旧 `error` 字段时，前端优先识别新字段；最终界面不得依赖旧中文文本。
- 操作摘要携带动作代码、路径、数量、请求／完成／失败状态及组合关系，由前端格式化。不是给现有中文字符串套一层替换表。
- `exec_presentation.py` 目前存在按空格拆分摘要、添加中文前缀及截断标签的逻辑，需要改为基于结构化字段组合；不能让翻译改变操作关联或分类。
- 无法估价原因用稳定 reason code 聚合，展示时再翻译；统计结果不因语言不同而改变分组或缓存键。
- 系统及外部工具的原始错误保留为诊断明细，外围产品说明可翻译；未知错误用通用可翻译消息兜底，不伪装成已完整翻译。
- 本地文件目录页目前由服务端输出 HTML，也需纳入覆盖：复用本地语言运行时渲染页面文字，不另建两套 HTML。初始语言与主页面采用同一规则。

## 日期、数字与图表

- 统一使用语言配置对应的 `Intl` 格式化入口，移除分散的 `'zh-CN'`、中文月份／星期及手工数字后缀。
- 界面语言与统计时区分开；切换语言不改变日期归属、聚合时区、金额币种、价格口径或原始精度。
- 日期桶仍以 `YYYY-MM-DD`、小时桶仍以现有稳定键传输；显示标签才本地化。不要把本地化数字或日期重新解析为业务输入。
- 格式化配置明确精度、百分比、紧凑数字及货币显示规则；表格与图表使用一致入口，未知金额继续保持未知。
- 翻译人员可配置轴标题、月份／星期标签和无障碍描述；坐标值、颜色与计算逻辑继续由代码负责。

## 第三方组件

列出 Schema Viewer、noUiSlider 等真正展示给用户的第三方字符串。优先使用上游支持的语言参数；自有适配器接收当前 locale 与翻译入口。无法配置的第三方文字需要逐项记录解决方式，不能遗漏后直接宣称整站完成。

不复制 vendor 组件生成英语版本，不对压缩产物做盲目字符串替换。若修改 Schema 适配器，按现有流程统一重新打包并保留许可证。

## 翻译交接约定

实施人员负责 key 清单、基准文案提取、上下文说明与占位符声明；翻译人员填写对应配置值。本文不预先承诺词条数量，完成提取后再统计。

交付模板需包含：key、基准文案、目标值、用途、参数名及类型、复数规则、长度建议、是否已审校。空值表示未完成。译文不得修改 key、参数名、代码、路径或品牌名称。

在 `messages.meta.json` 中维护术语约定，至少覆盖 session/thread、turn、tool call、orchestration、cache、credits、estimated cost；具体译法留待翻译人员确定。

## 实施阶段与验收

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| 1. 盘点 | key 与语义字段清单、翻译模板 | 覆盖前端、后端生成标签、demo 和第三方组件 |
| 2. 基础设施 | 配置加载、选择、回退、格式化及检查脚本 | 不依赖新构建步骤；语言切换和资源失败行为可验证 |
| 3. 主界面迁移 | 静态页面、动态界面与无障碍文案接入 | 中文行为保持，缺失项可追踪 |
| 4. 数据协议迁移 | 操作描述、错误与统计原因代码 | 相同记录在不同语言下的语义字段、数量、关联结果一致 |
| 5. 翻译填充 | 由翻译人员完成英语配置 | 无空值、占位符一致、复数分支完整，方可启用 |
| 6. 综合验收 | 浏览器、回归及发布包验证 | 通过下列检查后才称“完整支持英语” |

验收框架：

- 配置校验：未知 key、缺失 key、空值、重复 JSON key、错误类型、参数遗漏和错误复数分支均可报错；未启用语言允许保持待填状态。
- 单元回归：语言匹配、localStorage 不可用、回退、非法参数、转义及格式化边界；统计、分类及关联不受语言影响。
- 接口回归：普通错误、流式错误、价格下载错误及后端生成摘要；用户原文和工具原始输出保持逐字一致。
- 浏览器覆盖：主列表、工具详情、上下文／Schema、子代理预览、搜索、统计、价格设置、本地文件目录页和 demo；检查普通文字、tooltip、表单与无障碍名称。
- 布局覆盖：1280px 与 390px、深浅色、键盘及触屏路径；加入文本加长的伪语言测试，检查按钮、图表及浮层溢出。
- 完整度检查只扫描产品文案，不把原文、品牌名、代码或第三方原始数据误判为翻译遗漏。
- 公开导出包包含所有启用语言、manifest、验证工具及测试；空 CODEX_HOME 下的 demo 可独立验证；没有 CDN 翻译请求。
